# 세미나 셸 이식 — 레이아웃 전면 재구축 디자인 스펙

- 날짜: 2026-08-19
- 상태: 검토 대기
- 대상: martinmlops.github.io (Jekyll + minimal-mistakes 4.26.2 remote_theme)
- 소스: `내부세미나_분임조5조.html`의 셸 구조 (git 미추적, 참조용)
- 선행: [`2026-07-13-seminar-design-port-design.md`](2026-07-13-seminar-design-port-design.md)

## 배경

2026-07-13 스펙으로 세미나의 **디자인 토큰**은 이미 이식됐다. `_tokens.scss`의 값은
세미나 원본 `:root`와 완전히 일치한다. 그럼에도 "테마 쓴 블로그" 느낌이 남아 있다.

원인은 그 스펙이 명시적으로 제외한 항목이다.

> 범위 제외 (YAGNI) — 레이아웃 구조 변경 (사이드바·마스트헤드 배치는 현행 유지)

즉 **남은 격차는 색·타이포가 아니라 골격**이다. 이 스펙은 그 제외 항목을 다룬다.

### 관찰된 증거 (2026-08-19)

라이브 사이트를 직접 확인해 얻은 사실이다.

| 관찰 | 내용 |
|---|---|
| 세미나에 있고 블로그에 없는 것 | 52px sticky 헤더, `CONTENTS` 레일, mono 대문자 eyebrow, 번호 매긴 섹션(`01`/`02`), 헤어라인 카드 |
| 컴포넌트 사용률 | `_components.scss`의 카드·칩·콜아웃이 정의는 돼 있으나 **MM 레이아웃이 배치할 자리를 만들지 않아 사실상 미사용** |
| 포스트 페이지 좌측 | 대형 원형 아바타 저자 카드 — 세미나엔 저자 카드 개념 자체가 없음 |
| 목차 | 파란 채움 위젯(`On This Page`), 항목마다 테두리 — 세미나는 헤어라인 텍스트 내비 |
| 홈 우측 | 1440px에서 약 330px 빈 영역 |
| 검색 입력 | 존재하나 대비가 거의 없어 보통 배율에선 빈 화면으로 읽힘 |
| 검색 한국어 | `Terraform` → 4건 정상 / `쿠버네티스` → 0건 (해당 포스트 3편 존재) |
| 검색 빈 상태 | 새 쿼리가 0건이면 **이전 결과가 그대로 남음** |
| 다크모드 | `prefers-color-scheme` 미지원 — 토글한 적 없으면 OS가 다크여도 라이트 |

검색 한국어 실패의 원인은 lunr이다. 기본 trimmer가 `\W` 기반이라 한글 토큰을 잘라내고,
스테머도 영어용(`lunr-en.js`)이다. 본문의 약 70%가 한글인 블로그에서 검색이
라틴 문자에만 동작하고 있다.

## 목표

1. 세미나의 셸(52px sticky 헤더 + `CONTENTS` 레일 + 본문 2단)을 전 페이지에 적용한다.
2. minimal-mistakes의 레이아웃·CSS 의존을 제거해 특이도 충돌을 끝낸다.
3. 검색을 한국어에서 동작하게 만들고, 전송량을 줄인다.
4. 기존 글 31편은 **본문 무수정**으로 새 셸에 얹힌다.

## 1. 셸 구조

```
_layouts/default.html
├─ <head>                    seo-tag · Pretendard · 테마 사전적용 인라인(FOUC 방지)
├─ _includes/header.html     52px sticky, backdrop blur
│                            좌: 로고  |  우: mono 메타 · 검색 · 테마 토글
├─ .layout
│   ├─ _includes/contents-rail.html
│   └─ <main>{{ content }}</main>
└─ _includes/footer.html     현행 3단(CATEGORIES/LINKS/ABOUT) 유지, 헤어라인 재스타일
```

### 레이아웃 4종

| 파일 | 역할 | 적용 |
|---|---|---|
| `default.html` | 셸 | 전부의 base |
| `post.html` | eyebrow · 대형 타이틀 · 메타 · 본문 · 댓글 | 포스트 31편 |
| `page.html` | 타이틀 · 본문 (날짜·댓글 없음) | `_pages` 20개 |
| `home.html` | 페이지네이션 포스트 목록 | `index.html` |

**이관 방식** — 실측 결과 포스트 31편은 **한 편도 front matter에 layout을 적지 않고**
전부 `_config` defaults를 탄다. 따라서 `_config.yml` 한 줄(`single` → `post`)로 31편이
한 번에 옮겨진다.

`_pages` 20개의 내역과 처리는 다음과 같다.

| 대상 | 수 | 처리 |
|---|---|---|
| `layout: single` 명시 | 18 | `layout: page`로 일괄 치환 |
| `layout: tags` (`tags.md`) | 1 | `layout: page`로 변경, 태그 렌더링은 본문 Liquid로 |
| layout 미명시 (`about.md`) | 1 | `_config`의 `_pages` scope default를 `single` → `page`로 바꾸면 자동 적용 |

### CONTENTS 레일 규칙

레일이 비는 페이지가 없어야 하므로 단일 규칙으로 고정한다.

> **h2가 2개 이상인 페이지 → 그 페이지의 목차. 그 외 → 사이트 내비(카테고리).**
> 테마 토글은 어느 쪽이든 레일 하단 고정.

목차는 `main`의 `h2`/`h3`를 클라이언트에서 읽어 생성한다. `h2`는 `01`, `02` … 번호를
mono로 붙이고, `h3`는 들여쓴 하위 항목으로 둔다. 스크롤 위치에 따라 현재 항목을 강조한다.

모바일(< 768px)에서는 2단이 성립하지 않으므로 레일을 헤더 버튼으로 여는 드로어로 접는다.

## 2. 검색

### 인덱스

`search-index.json`을 Jekyll 페이지로 생성한다. 포스트 31편 + 페이지 20개.

```
{ t: 제목, u: URL, d: 날짜, c: 카테고리[], g: 태그[], h: 헤딩[], e: 요약, b: 본문(strip_html) }
```

`h`는 본문의 `h2`/`h3` 텍스트만 뽑아 담는다. 스코어링에서 본문보다 높은 가중치를
받으므로 별도 필드가 필요하다.

### 로딩

헤더의 검색을 **처음 열 때 한 번** `fetch`한다. 현재는 553KB `lunr-store.js`를 모든
페이지에서 무조건 받고 있으며, 이것이 0이 된다. 인덱스는 메모리에 캐시한다.

`fetch` 실패 시 오버레이에 `인덱스를 불러오지 못했습니다 · 다시 시도`를 표시한다.

### 매칭

순수 함수로 격리해 단위 테스트한다. 부작용도 DOM 접근도 없다.

```
search(index, query) → results[]

정규화   NFC 정규화 + 소문자 + 앞뒤 공백 제거 + 연속 공백 축약
분리     공백 기준 분할 → 모든 항이 포함돼야 매치 (AND)
매칭     부분문자열 (형태소 무시 → "임베딩"이 "임베딩은"에 매치)
점수     제목 ×8 · 헤딩 ×4 · 태그/카테고리 ×3 · 요약 ×2 · 본문 ×1
정렬     점수 내림차순, 동점이면 날짜 내림차순
반환     상위 20건 + 첫 본문 매치 주변 스니펫
```

### UI

세미나풍 오버레이. mono eyebrow `SEARCH`, 헤어라인 테두리가 **보이는** 입력창,
결과 수를 mono로 `4 RESULTS`, 행마다 카테고리 칩 · 제목 · 날짜 · 스니펫(`<mark>` 강조).

키보드: `/` 또는 `⌘K` 열기, `↑` `↓` 이동, `Enter` 열기, `Esc` 닫기.

**빈 상태를 명시적으로 처리한다.** 입력이 비면 결과도 비운다. 0건이면 0건 상태를
그린다. 현재의 "이전 결과가 남는" 동작을 제거한다.

JS가 없으면 검색 버튼을 렌더링하지 않는다.

## 3. 테마

| 상태 | `<html>` | 결과 |
|---|---|---|
| 명시적 다크 | `data-theme="dark"` | 다크 고정 |
| 명시적 라이트 | `data-theme="light"` | 라이트 고정 |
| 미선택 (기본) | 속성 없음 | `prefers-color-scheme` 따름 |

토큰은 `:root`에 라이트 전체를 정의하고, `@media (prefers-color-scheme: dark)`와
`[data-theme="dark"]` 두 곳에서 **같은 변수만** 덮는다. 어떤 색도 미디어 쿼리 안에서만
정의되지 않게 한다.

수정 지점 4곳: `_tokens.scss`, `assets/js/theme-toggle.js`,
`_includes/head/custom.html`(FOUC 방지 인라인), `assets/js/mermaid-init.js`(`isDark` 판정).

## 4. 구현 순서

`redesign/seminar-shell` 브랜치. 각 단계는 독립적으로 빌드·확인·커밋한다.

| # | 만드는 것 | 확인 대상 |
|---|---|---|
| 1 | `default.html` 셸 + `post.html`, 헤더·레일·푸터 include, 테마 3-상태 | 포스트 1편 |
| 2 | `page.html` (+`tags` 흡수), `_pages` 20개 이관 | 카테고리 랜딩 · 토픽 허브 · about · tags |
| 3 | `home.html` + 페이지네이션 | 홈, `/page2/` |
| 4 | `@import "minimal-mistakes"` 제거, 잔여 CSS 정리 | 전 페이지 재확인 |
| 5 | 검색 교체 (인덱스 · 매칭 · UI) | 한/영 쿼리, 빈 상태, fetch 실패 |
| 6 | `remote_theme` 제거, Gemfile · `_config` 정리, 기존 테스트 갱신 | 빌드 + 전 페이지 |

MM CSS 제거를 4단계로 미루는 이유: 1~3단계에는 우리 레이아웃과 MM 레이아웃이 공존하지만
우리 레이아웃이 MM 클래스를 쓰지 않으므로 임포트가 남아 있어도 무해하다. MM 클래스를 쓰는
마지막 레이아웃이 사라진 뒤 걷어내는 편이 안전하다.

## 5. 테스트

| 층 | 도구 | 검증 |
|---|---|---|
| 단위 | vitest | `search()` 정규화 · AND 매칭 · 점수 · 정렬 · 빈 쿼리 · 0건 |
| 산출물 | jest (`__tests__/utils.js` 확장) | 인덱스 JSON 스키마 · 전 포스트가 새 layout으로 해석 · `_site`에 MM 클래스(`page__content`, `archive__item`) 잔존 0 · `lunr` 참조 0 |
| 화면 | claude-in-chrome | 아래 체크리스트 |

**첫 실패 테스트**: `search(index, "쿠버네티스")`가 3건 이상을 반환할 것. 현재 0건.

산출물 층이 중요하다. "MM 클래스가 하나도 남지 않았는가"는 기계적으로 단언할 수 있고,
자동 시각 회귀가 없는 이 프로젝트에서 이관 완료를 보증하는 유일한 자동 장치다.

### 화면 체크리스트

7종 × 라이트/다크 × 1440px/375px. 단계마다 해당 페이지만, 4단계와 6단계에서 전체.

홈 · 포스트 · 카테고리 랜딩 · 토픽 허브 · tags · about · 검색 오버레이

각 컷에서 확인: sticky 헤더 동작, 레일이 비지 않는지, 본문 폭·여백, 표·코드블록 가로 넘침,
mermaid 팔레트, 이미지 반응형, 푸터.
